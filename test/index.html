Test RC Pair

RC Pair pairs an iPhone or iPad with a computer you choose, so an AI coding agent on that computer can work with the phone. This page is for developers who installed the TestFlight build and have a computer with an agent such as Claude Code or Codex.

The five steps on the phone take about five minutes. Building the tools and getting Apple's disk image take longer. The list near the bottom says what is still rough.

What you need

An iPhone or iPad on iOS or iPadOS 17 or later, and the TestFlight build.

Open the TestFlight link

The phone has to be on Wi-Fi. A hotspot from another phone works. The phone's own cellular data does not.

A Mac or Linux computer the phone can reach on a private address, usually the same Wi-Fi. It needs Python 3.9 or later, git, and an AI coding agent. The phone sends only to a private address and refuses a public one.

To go past pairing you also need a recent Rust toolchain (1.85 or later, from rustup) and a C compiler to build the tools, Apple's developer disk image, and for the one-time disk image step a USB cable to the computer. On Linux that step also needs the usbmuxd service. The computer section below covers each one.

Set up the phone

RC Pair walks you through five steps. Allow Local Network access when the phone asks.

  1. Allow notifications.
  2. Make Developer Mode appear. Tap Make it appear in RC Pair.
  3. Turn on Developer Mode and restart. Turn it on in Settings, and the phone restarts once. Open RC Pair again after the restart.
  4. Pair. In Settings, go to Privacy & Security > Developer Mode, tap RC Pair under Other Devices, then tap Pair. RC Pair shows a 6-digit code, and you type it in Settings.
  5. Scan your computer’s QR code with the Camera app. Start the receiver from the computer section below first, because this step needs it running.

On iOS 17 to 25, RC Pair gets about 30 seconds once you leave it, so go straight to Settings when it sends you there. On 26 and later it keeps running while you are in Settings.

Set up your computer

Step 5 needs rcpair-receive running on your computer. It is in phone-open, the companion repo for RC Pair, which is source available under the Functional Source License. Clone it and start the receiver. On Debian or Ubuntu, install python3-venv first.

git clone https://github.com/rcpair/phone-open.git
cd phone-open
python3 -m venv .venv
.venv/bin/pip install cryptography qrcode
.venv/bin/python scripts/rcpair-receive.py

The script shows a QR code and a link, then waits ten minutes for one upload. On the phone, scan the QR code with the Camera app and tap Open in RC Pair, or copy the link and tap Paste link in RC Pair. Check the computer's name and address, then tap Send. The script saves the pairing in ~/.rcpair and exits. If you only want the script, it is also at rcpair.si/review/rcpair-receive.py.

Next, in the same folder, get the tools and Apple's disk image.

scripts/fetch-deps.sh
scripts/ddi-from-xcode.sh --mac you@your-mac
scripts/connect.sh

The second line copies the disk image from a Mac with Xcode over ssh. Run it without --mac if you are on that Mac. Xcode has to have prepared a device once (Window > Devices and Simulators shows it ready) before the image is there to copy. Skip the second line if you have no Mac. When the image folder is empty, connect.sh runs scripts/ddi-from-github.sh for you, which pulls a pinned copy of Apple's file from a third party's GitHub repo and checks it against hashes in phone-open. Set RCPAIR_DDI_FETCH=0 to stop that.

The third line builds the tools, which is slow the first time, and prints the remaining steps. The README and docs/ARCHITECTURE.md in the repo go through each one.

What to try once it works

First, finish step 5 and check that ~/.rcpair holds a .rppair.plist file and a .json file for your phone. That is the pairing hand-off, and it is the part the app covers.

Then follow the steps connect.sh prints to open the tunnel and put the disk image on the phone. After that, give your agent the idevice tools for reading the screen, tapping, dragging, typing and launching apps, and see how far it gets on a simple task such as opening an app and searching in it.

What does not work yet

  • There is no packaged driver, MCP server or agent hookup. phone-open gives your agent the tools. What to tap is up to your agent.
  • With the pinned tools the disk image goes onto the phone over USB, or from Xcode on a Mac. An iOS update removes it, and it goes back on the same way.
  • Changing networks can mean pairing again. Across a VPN such as Tailscale, use the computer's IP address, because device discovery does not cross a VPN.
  • scripts/rcpair-session.sh cannot work with the pinned tools and exits with status 3.

Tell us where you got stuck

The most useful report is the step where you stopped, what the screen or terminal showed, and the phone model, iOS version and computer you used. Send it to support@rcpair.si, or take a screenshot in RC Pair and send it as TestFlight feedback. A short note is enough. Please do not send the saved pairing files.
