Test RC Pair

RC Pair pairs an iPhone or iPad with a computer you choose, so an AI coding agent on that computer can work with the phone. This page is for developers who installed the TestFlight build and have a computer with an agent such as Claude Code or Codex.

The five steps on the phone take about five minutes. On a Mac, the computer side is now an app you download and open. The list near the bottom says what is still rough.

What you need

An iPhone or iPad on iOS or iPadOS 17 or later, and the TestFlight build.

Open the TestFlight link

The phone has to be on Wi-Fi. A hotspot from another phone works. The phone's own cellular data does not.

A Mac the phone can reach on a private address, usually the same Wi-Fi, with an AI coding agent such as Claude Code or Codex. The phone sends only to a private address and refuses a public one. Linux has a downloadable program with no window, on the computer page. Windows is not ready yet.

Apple's developer disk image goes on the phone before an agent can drive it. The Mac app gets it for you from Xcode or from GitHub. The source route on Linux also needs a Rust toolchain, a C compiler and, for the one-time disk image step, a USB cable and the usbmuxd service.

Set up the phone

RC Pair walks you through five steps. Allow Local Network access when the phone asks.

  1. Allow notifications.
  2. Make Developer Mode appear. Tap Make it appear in RC Pair.
  3. Turn on Developer Mode and restart. Turn it on in Settings, and the phone restarts once. Open RC Pair again after the restart.
  4. Pair. In Settings, go to Privacy & Security > Developer Mode, tap RC Pair under Other Devices, then tap Pair. RC Pair shows a 6-digit code, and you type it in Settings.
  5. Scan your computer’s QR code with the Camera app. Set up your computer first (the section below), because this step needs its QR code on screen. On a Mac, open RC Pair and click Add a phone. On Linux or a server, run rcpair receive.

On iOS 17 to 25, RC Pair gets about 30 seconds once you leave it, so go straight to Settings when it sends you there. On 26 and later it keeps running while you are in Settings.

Set up your Mac

Download the RC Pair computer app. No terminal, Python or Xcode needed for this part.

Download RC Pair for Mac

macOS 12 or later, Apple silicon or Intel. 15 MB. Signed with our Apple Developer ID and notarized by Apple. The checksum and signature steps are on the computer page.

  1. Open the downloaded file and drag RC Pair to Applications.
  2. Open RC Pair from Applications. macOS asks once whether you want to open an app downloaded from the internet. Choose Open.
  3. Tick the box on the first screen and click Continue.
  4. Click Add a phone. The app shows a QR code. If your Mac asks to let RC Pair find devices on your local network, or to accept incoming connections, click Allow.
  5. On the phone, do step 5: scan the QR code with the Camera app and tap Open in RC Pair, check the computer's name, and tap Send. The app says Phone added. If RC Pair says there is no pairing to send, or that it already went to another computer (for example because you ran rcpair-receive.py before), tap Start over in RC Pair and pair again in Settings.
  6. Under Apple's disk image, click Copy from Xcode on this Mac if you have Xcode, or Download from GitHub. The download is a pinned copy of Apple's file from a third party's GitHub repo, and the app checks every file against fingerprints built into it.
  7. Under Connect your agent, copy the line for Claude Code or Codex into your agent.

Pairing and the disk image are tested. Driving a phone from the Mac app has not been run with a phone yet, because we have no Mac with a phone here. Your Mac is the first. If the agent cannot reach the phone, tell us what it said (the last section has how).

While an agent is working the phone, its camera and microphone are paused. They come back about 10 seconds after the agent's last tap.

Linux, or building from source

The simplest Linux route is the rcpair program on the computer page. There is no Windows app yet. This is the older route: the receiver script from phone-open, the companion repo for RC Pair, which is source available under the Functional Source License. On Debian or Ubuntu, install python3-venv first.

git clone https://github.com/rcpair/phone-open.git
cd phone-open
python3 -m venv .venv
.venv/bin/pip install cryptography qrcode
.venv/bin/python scripts/rcpair-receive.py

The script shows a QR code and a link, then waits ten minutes for one upload. It saves the pairing in ~/.rcpair and exits. If you only want the script, it is also at rcpair.si/review/rcpair-receive.py. Then get the tools and Apple's disk image:

scripts/fetch-deps.sh
scripts/ddi-from-xcode.sh --mac you@your-mac
scripts/connect.sh

The second line copies the disk image from a Mac with Xcode over ssh. Skip it if you have no Mac: when the image folder is empty, connect.sh runs scripts/ddi-from-github.sh, which pulls the same pinned third-party copy and checks it against hashes in phone-open. Set RCPAIR_DDI_FETCH=0 to stop that. The third line builds the tools and prints the remaining steps.

What to try once it works

First, finish step 5. The Mac app lists the phone under Phones once the pairing arrives.

Then add RC Pair to your agent with the line from Connect your agent, keep the phone unlocked on the same Wi-Fi, and ask the agent for something simple, such as opening an app and searching in it.

What does not work yet

  • The Mac app is signed and notarized, but we have not opened it on a real Mac yet.
  • Driving a phone from the Mac app has not been run with a phone yet. Your report is the first.
  • Windows is not out yet. It needs a real test on a Windows computer and a signing certificate.
  • An iOS update removes Apple's disk image from the phone, and it has to go back on.
  • Changing networks can mean pairing again. Across a VPN such as Tailscale, use the computer's IP address, because device discovery does not cross a VPN.
  • scripts/rcpair-session.sh cannot work with the pinned tools and exits with status 3.

Tell us where you got stuck

The most useful report is the step where you stopped, what the screen or terminal showed, and the phone model, iOS version and computer you used. Send it to support@rcpair.si, or take a screenshot in RC Pair and send it as TestFlight feedback. A short note is enough. Please do not send the saved pairing files.
